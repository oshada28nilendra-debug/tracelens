# TraceLens

Offline distributed-trace inspection for developers investigating a slow request across services. Import one OTLP JSON export, reconstruct span trees and generate a standalone HTML timeline plus a JSON bottleneck-candidate report. No collector, paid cloud, credentials or third-party service required.

## Run

Python 3.11+; standard library only. From the repository folder:

```bash
python tracelens.py examples/checkout.json --slow-ms 100
python -m unittest discover -s tests -v
```

Open `outputs/report.html` in your browser. `outputs/report.json` contains the same evidence for further analysis. Use your own export as the positional input. Flags `--output` and `--html` change output paths. Reports are overwritten on rerun; input and output paths must differ. No source trace file is changed. The report works offline with no JavaScript or external assets.

## Supported input contract

One [OTLP/HTTP JSON ExportTraceServiceRequest](https://opentelemetry.io/docs/specs/otlp/#json-protobuf-encoding): `resourceSpans[] → scopeSpans[] → spans[]`. This is not Jaeger JSON, Chrome tracing JSON, newline-delimited Collector output, or the SDK console-exporter format. Extract a single OTLP request before import.

- `resource.attributes`: `service.name` with `value.stringValue`, otherwise `unknown-service`.
- Each span requires nonzero hexadecimal `traceId` (32 digits), `spanId` (16), nonempty `name`, `startTimeUnixNano` and `endTimeUnixNano`.
- Times are unsigned decimal nanoseconds (strings preferred; integers accepted). Python integer arithmetic preserves nanosecond precision before conversion to relative milliseconds.
- `parentSpanId` is empty/absent for roots, otherwise a 16-digit nonzero hex ID.
- `status.code` uses numeric OTLP enums: 0 unset, 1 OK, 2 error; absent means unset.
- Extra fields, events, links, span kind and attributes other than service name are ignored. This is a documented subset, not a complete OTLP schema validator.
- CLI limit: 10 MiB input; analysis limit: 10,000 spans.

See `examples/checkout.json` for a full **synthetic** distributed-service example. `python sample.py` reproduces it. Original synthetic fixture is CC0-1.0.

## Reports and interpretation

The HTML shows parent/child indentation, relative timelines, duration, uncovered duration, errors, configurable slow-span flags, repeated service/name operations and data-quality warnings. JSON includes IDs for every candidate so evidence remains traceable.

Uncovered duration = span duration minus the **union** of direct-child intervals, clipped to the parent. Overlapping concurrent children must not be subtracted twice. This measurement is not CPU time, critical-path duration or causal root cause. Missing instrumentation and clock skew can distort it. Inclusive span durations overlap, so summing them across services does not yield request latency.

Repeated names are grouped per trace and service; they may be expected calls, not necessarily retries or an N+1 defect. Slow uses an explicit threshold (default 100 ms), not a learned baseline. Error counts follow recorded status and may miss failures that were not instrumented.

Missing parents become visible roots with warnings; parents never cross trace IDs. Duplicate IDs keep the first accepted span and reject later copies with diagnostics. Malformed spans are skipped and counted. Malformed containers reject the request. Cycles are broken deterministically with a warning; spans are retained. Children outside their parent's time range trigger warnings and clipped accounting. Tree traversal is iterative, so deep input does not depend on Python recursion depth.

## Measured example

The committed `reports/sample-analysis.json` and HTML were generated by the CLI. The fixture has six spans across gateway, orders, database and payments, with a missing parent and one payment error. Expected results checked by tests:

| Evidence | Result |
| --- | --- |
| Observed trace envelope | 540 ms |
| Orders duration / uncovered | 460 / 70 ms |
| Gateway duration / uncovered | 500 / 40 ms |
| Largest uncovered candidate | charge, 210 ms |
| Repeated SELECT inventory | 2 calls |
| Missing-parent warning / errors | 1 / 1 |

This is a deterministic arithmetic/integration fixture, not a production performance benchmark. `analysis_seconds` is a measured local processing time and varies by machine. No deployment, user adoption or causal diagnosis claims are made.

## Architecture and trade-offs

`tracelens.py` parses and validates spans, indexes `(traceId, spanId)`, resolves parents, breaks cycles, computes interval unions and renders escaped HTML. `sample.py` supplies original test inputs. Unit and CLI tests cover overlap, malformed data, cycles, missing parents, duplicate IDs, trace isolation, zero duration and HTML escaping. GitHub Actions repeats tests and exports report artifacts.

In-memory processing and per-trace grouping suit small incident exports; large fleets need indexing, persistence and sampling-aware aggregation. Reports contain service names and operation labels from the input: review sensitive telemetry before sharing. No network calls occur during analysis.
